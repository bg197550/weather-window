# weather-window
NOAA outlooks and local forecasts for Utah and New England

## Navigation

Every page shares one section bar: **Forecast · Radar · Webcams · Snow report · Precip models · Long range**, with a Utah / New England switch. On phones it becomes a bottom tab bar (Forecast, Radar, Cams, Snow, More); Precip models, Long range, the region switch and a Surf link sit under More. The region you pick is remembered on the device and used by every page, and Forecast reopens the last place you viewed in that region. With no link, the site opens on the forecast and, if location access is allowed, jumps to the closest listed place.

## What's on the dashboard

- **Forecast** (`#utah/...`, `#ne/...`): location pills on desktop, a location dropdown (both regions) on phones, plus a ⌖ closest-forecast button and refresh. The overview shows current conditions, the next 24/48 hours and a 7-day strip (one tile per day with high, low and precipitation chance). On desktop these share one screen; on phones they stack in that order, and resorts with separate peak and mid-mountain forecasts get one Peak / Mid toggle that switches all three. Detailed forecast, the full Area Forecast Discussion, model comparison and (Utah) mountain profile are tabs on desktop and a "More for …" list on phones. Each resort links to its webcams, the snow report and the avalanche forecast.
  - **Same-grid points**: NWS forecasts use ~2.5 km grid squares. When a resort's peak and mid-mountain points fall in the same square they are shown as one forecast ("Peak & mid mountain") instead of two identical cards.
  - **Grid elevation note**: when the NWS grid averages 500 ft or more below (or above) a point, the card says so, e.g. Stowe's summit grid is about 1,000 ft below Mt. Mansfield.
  - **Observations**: each Utah point tries on-mountain stations first (`OBS_STATIONS` in `assets/common.js`), then the NWS nearest-station list. Readings older than 2 hours are not shown as current; the card says no station has reported recently.
- **Radar**: NOAA NEXRAD base reflectivity loop (last 50 minutes) from the Iowa Environmental Mesonet on an OpenStreetMap basemap, with presets for the Wasatch, northern Utah, Boston, and southern/northern New England, plus the NWS station loops and an embedded [Windy](https://www.windy.com/) radar map. Place names are labeled on the map; labels that would overlap are hidden until you zoom in.
- **Webcams** (`webcams/`): resort cameras for Utah and New England (Killington, Stratton, Stowe, Jay Peak, Bromley, Gunstock, Loon, Sunday River, Sugarloaf, Wachusett, Ski Sundown and Mohawk Mountain). Feeds are the resorts' own public embeds (HDRelay, YouTube, CamStreamer, Brown Rice, WetMet, Angelcam, Roundshot, PrismCam); HDRelay cameras play live video and fall back to a 30-second still if the stream drops.
- **Precip models**: a table of all 10 models at every forecast location (bold = highest model at that place; click a model to map it), then the selected model's map with its legend on top, and the Windy animation.
- **Long range**: CPC outlook maps and the briefing generated by `scripts/update-long-range.mjs`. The page flags the briefing as stale if it is more than 12 hours old or if parts could not be refreshed.

The URL keeps the current section, location and view (for example `#utah/deer-valley/mountain`), so views can be bookmarked. Open pages refresh their data every 15 minutes while visible. No API keys are used.

## Snow Report (`snow/`)

Resorts (NWS gridded snowfall 24/48/72 h at mid-mountain and peak, snow level, avalanche links, mountain alerts), Models (16-day GFS / ECMWF / AIFS / GEM snowfall by resort), Snowpack (measured USDA NRCS SNOTEL depth, 24 h and 7-day change, SWE) and Hourly (NWS 48-hour chart plus the point forecast for any resort). Utah only.

## Offline

`sw.js` keeps the last copy of each page and of the forecast data (NWS, Open-Meteo, the long-range and SNOTEL files), so the dashboard still opens without signal; a banner says you're offline and each card keeps its issue time. Map tiles, radar loops, webcams and videos are never cached.

## Data jobs

Both GitHub Actions jobs publish to the `data` branch (not `main`), so refreshes don't add commits to the site's history or trigger site rebuilds, and they run one at a time so neither overwrites the other's file:

- `.github/workflows/update-long-range.yml` → `data/long-range.json` every 6 hours. The script parses each CPC horizon and each region's ensemble guidance independently; if a source is unreachable it keeps the previous data for that part and records it in `warnings`.
- `.github/workflows/update-snotel.yml` → `data/snotel.json` hourly.

The copy of `data/long-range.json` on `main` is only a fallback.

## Code layout

| File | What it holds |
| --- | --- |
| `index.html`, `snow/index.html`, `webcams/index.html` | Page markup only |
| `assets/nav.js`, `assets/nav.css` | Shared section bar, phone tab bar, remembered region, offline banner, service worker registration |
| `assets/common.js` | Locations, observation stations, resort→webcam links, and helpers shared by the Weather and Snow pages (NWS requests, hourly chart, resort snow table, snowfall models) |
| `assets/app.js`, `assets/app.css` | Weather page (forecast, radar, precip models, long range); `app.css` is also the Snow page's base stylesheet |
| `assets/snow.js`, `assets/snow.css` | Snow Report page |
| `assets/webcams.js`, `assets/webcams.css` | Webcams page and camera list |
| `sw.js` | Offline cache |

Asset links carry a `?v=` date; bump it in the three HTML files when you change an asset so phones don't mix old and new files.

The app bar (Weather / Surf / Snow and Ask AI) comes from the shared `suite.css`/`suite.js` served by Surf Window. New England locations include NH Seacoast (North Hampton), which the Surf Window beaches in New Hampshire link to.
